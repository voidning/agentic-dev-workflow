# 独立验收协议

本协议仅在需要独立验收或对应成果验证方法时读取相关部分；实现稳定并完成自检后再集中验收。传给验收者的是下面的中立任务包与当前任务所需的最少上下文，默认使用新上下文，不复制完整实现聊天；任务包仅填写与本次检查有关的信息，合并简短项，不补写无用背景。

## 委派任务包

```text
你是本次变更的独立验收者，不参与实现。请基于需求独立取证，不以实现者的完成声明作结论。

原始需求与已确认取舍：<保留用户原意和关键约束>
验收条件与保留行为：<逐项列出可观察结果>
被验收目标与类型：<代码/Skill/提示词/配置/自动化；目录、提交号或文件快照，包含相关未提交改动>
基线：<原有行为、已知失败及其证据；未知明确标注>
允许范围：<只读成果与允许运行的本地检查；临时证据写入的隔离位置>
启动与验证入口：<相关命令、加载方式、模型/工具环境、测试数据和正常使用入口>
停止条件：<成本、时长或操作边界；缺少权限/数据时停止对应检查>

自行阅读相关实现，对照需求独立运行关键检查，并寻找合理的遗漏和边界。
不要修改被验收成果、已有测试或验收标准；不要发布、操作真实用户数据、安装或更改全局配置。
测试可能写入状态时先确认已授权的隔离数据与运行方式，不能确保时报告受阻。
不继续委派任务，除非协调者另有明确安排。

输出：目标版本、总体状态（通过/退回/受阻）、逐项覆盖、实际运行证据、缺陷及限制。
缺陷写明需求依据、复现条件与步骤、预期/实际、影响；推测与建议分别标注。
不要通过评分、赞美或仅阅读源码/指令替代行为证据。完成后说明成果与环境是否发生变化。
```

有 Git 时用提交号加工作区差异标识目标；无 Git 时用相关文件快照或哈希。不要只报任务开始时的提交号而忽略后来改动。验收和交付之间出现相关成果、配置或数据变化，重新判断哪些验收失效。文件已安装与实际运行环境已加载该版本分别确认，不能用复制成功证明自动触发或运行行为。

## 选择必要证据

| 类型 | 关键证据 | 常见错误 |
| --- | --- | --- |
| Bug | 可行时旧版失败、新版同条件通过；确认失败来自目标缺陷 | 把环境报错当回归，把新样例通过当原症状消失 |
| 业务/接口 | 正常输入、关键边界与失败路径；检查状态、输出或持久化结果 | 只验证返回成功，不检查结果 |
| UI/交互 | 正常入口操作、相关屏幕状态、实际渲染，与已认可样板对照 | 只看代码或静态图，跳过交互 |
| 状态/存档/迁移 | 隔离副本上的旧数据兼容、前后结果及必要恢复验证 | 在真实数据上实验，或只测试新建数据 |
| 性能 | 同环境、同负载的前后测量，说明样本与波动 | 无测量宣称更快，或任意放宽阈值 |
| 架构/重构 | 项目约定、依赖/状态边界、外部行为保持证据 | 用个人风格偏好要求范围外重写 |
| Skill/提示词 | 文件与引用有效、规则无冲突；代表性任务的触发与执行证据 | 只验证 Markdown/YAML，或让模型口头承诺遵循 |
| Agent 配置 | 格式与实际加载值、覆盖关系、工具边界，隔离任务中的行为 | 配置可解析就声称已生效，或为验证扩大权限 |
| 自动化 | 隔离试运行的触发、输入、输出、失败和重复执行行为 | 启用真实定时任务才测试，或用干跑声称生产效果通过 |

按风险取舍，不机械跑遍所有类别。用模拟或内部钩子时说明它覆盖什么；真实路径仍需从正常入口验证。主观体验可以给有依据的评价，不能只凭另一个模型的认可宣称用户满意。

## 指令、配置与自动化的验证

分三层报告，按变更影响决定深度。低风险局部修改可做文件检查与规则审查，涉及判断规则时用少量代表性任务推演分流，无需搭建行为评测系统。高风险、跨模块复杂联动、反复失败或用户明确要求实际行为验证时，运行对应行为案例；必要验证缺少条件才标为待验收。独立验收是否必需按主 Skill 的风险分流决定，用户明确要求的检查不得省略。规则推演不能声称实际行为已验证。

1. **文件验证**：检查实际格式、必要元数据、引用与资源、脚本入口；保留已有无关字段。运行项目或制作技能已有的校验器，不能将格式检查宣传为行为评测。
2. **规则审查**：检查适用边界、指令冲突、不可执行要求、过度限制、范围扩张、权限假设和失效处理。协调流程与成果制作方法分别明确，避免重复或互相覆盖。
3. **行为验证**：在新上下文和隔离目录里让执行者实际使用候选成果完成代表性任务，记录操作与结果；需要独立验收时，由未参与实现的评判者按预先确定的标准判断。

行为案例按实际风险选择：

- 正向：应触发的任务，是否加载正确版本并完成可观察结果。
- 反向：不适用的任务，是否避免误触发和范围扩张。此类案例不能显式指定必须使用被测 Skill；只能验证当前测试入口所支持的触发机制。
- 异常：信息不足、工具不可用、权限受限或执行失败，是否正确处理并如实报告。
- 回归：旧版已支持的关键任务，修改后是否继续满足要求。

需要独立行为评测时，执行者收到正常用户任务、被测成果与必要原始材料，不收到预期答案或评分结论。评判者另持验收标准，检查实际产物与工具记录；同一次任务不能由同一 Agent 同时充当执行者和独立评判者。给执行者的候选指令不能覆盖测试环境的范围与操作限制。

只允许一个子 Agent 时，可由它执行隔离行为案例并输出原始证据，主 Agent 按事先固定的标准复核；必须说明这是“独立执行＋主 Agent 复核”，不能宣称全流程盲审。需要完整独立行为评判时，另用未参与编写和执行的新上下文。当前工具无法隔离加载候选指令或无法委派时，报告对应限制，不通过创建其他用户任务或更改全局设置绕过。

预先确定通过条件、案例集合和可承担的运行预算；有随机性时在固定案例与可比环境下做有边界的重复，记录实际模型、参数和工具配置（可知时），不能挑一次成功或看完结果后放宽门槛。单次成功只证明该次运行，定向调用成功不证明自动发现成功。

自动化先使用固定输入、模拟事件和隔离输出进行试运行，检查适用的重复触发、重试上限、失败处理与幂等性。模拟时钟、外部服务替身和干跑分别标注覆盖限制。真实调度、通知、外部写入或发布需已有授权；它们是可分开的交付步骤。

修改本协作 Skill 时，验收者使用变更前固定的本轮任务包和标准评判候选版本；不把候选文件新增的“通过规则”作为自我认证依据。

## 判定与汇报

- **通过**：必要验收项有证据支持，没有本次阻断缺陷。列出实际覆盖，不能宣称未测试领域通过。
- **退回**：至少有一项已确认的需求遗漏、回归或目标缺陷。将问题交回实现者，验收者保持只读。
- **受阻**：必要检查缺环境、工具、数据或权限；或者现有失败阻碍判断。可以报告已通过的子项，整体不记为通过。

推荐简短报告：

```text
目标版本/快照：
总体状态：
验收项：条件 → 实际检查 → 结果 → 证据位置
已确认缺陷：要求 → 条件/步骤 → 预期/实际 → 影响 → 证据
推测项与非阻断建议：
未验证项、环境限制与原有失败：
运行产生的临时状态或文件：
```

证据附实际命令、退出状态、关键输出或可定位的截图/日志，不堆全文。子 Agent 的自述只是索引；协调者至少核实阻断缺陷和决定交付的关键证据。

## 争议与复验

实现者提供反证时，对照相同版本、环境、输入和步骤判断。不能复现的疑点标为待查；若它直接影响必要完成条件，保持受阻，不强行通过。

修复后只检查新版本上的原失败及受影响回归；无新改动、新失败或未解决风险不再全量复验。验收者可复用自己的失败记录，但应重新读取相关变化，不只重读实现者解释。若当前验收者实际参与了修复，改由未参与实现的新上下文验收。

## 维护时的行为评测

需要实际行为评测时，用隔离项目重放少量真实任务，给执行者正常任务描述；评判者另持已确认的预期结果。观察工具动作与产物，避免只匹配回答用词。

优先覆盖：局部变更是否越界、修复是否保留原失败证据、构造场景是否被冒充真实路径、最终代码是否与已验收版本一致、已有失败是否被隐藏。对无问题的任务也检查误报。

仅做规则推演或委派不可用、被禁止时明确记录“未做独立行为评测”；文件格式或人工检查不能替代这项结论。评测自身的运行范围、成本与副作用同样需要已有授权。
